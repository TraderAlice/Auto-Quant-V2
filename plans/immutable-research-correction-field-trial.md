- Target release: `0.9.17`

## Outcome

Prove whether a fresh quantitative coworker can consume one strict Independent
Review, correct a material published evidence-reference defect without
rewriting any prior evidence, and leave future Agents and humans one durable,
unambiguous current research handoff with exact correction lineage.

The exact released `0.9.16` wheel is the untouched baseline. `0.9.17` will
contain only the smallest coherent reusable repair justified by the trial.
Breaking replacement is allowed when the current Report model is wrong; no
compatibility layer or OpenAlice migration is required.

## Correction assignment

Give a fresh coworker:

- a byte-for-byte copy of the completed `reported-book-path-stress` Project
  and its Workspace staging history;
- the detached `0.9.16` Review package
  `review-20260801T081829692481Z-e779b0ca5dba`;
- the exact installed released `0.9.16` wheel;
- no original conversation, implementation checkout, private notes, or
  instruction about repository internals.

The coworker must answer:

> Close the P0 evidence-reference integrity defect identified by the supplied
> Independent Review. Preserve the original Report, Run, Review, data, and
> Workspace evidence byte-for-byte as immutable history. Do not acquire data,
> rerun research, create a Session, re-price OHLCV, optimize the book, or grant
> trading authority. Use only installed public AutoQuant surfaces. Publish one
> corrected durable primary-research handoff that retains every supported
> quantitative conclusion but removes the unsupported Nasdaq clause instead
> of promoting staging into authority. Make it unambiguous to a future Agent
> which handoff is current, what it corrects, why it changed, and which exact
> Review and prior Report caused the correction. Verify the result publicly
> and stop.

The baseline may use the best truthful representation currently available. It
must not be coached toward a presumed replacement, amendment, or supersession
implementation. Any loose note, duplicated current Report, ambiguous listing,
unverifiable correction claim, or need for private filesystem inference is
retained as product evidence rather than hidden.

## Scope

### In scope

- One isolated fresh Grok 4.5 correction worker using the exact installed
  `0.9.16` release wheel and copied frozen evidence.
- Public Review verification, Report/Run inspection, correction authoring,
  immutable publication, currentness/lineage discovery, CLI/Studio projection,
  and exact pre/post mutation inventory.
- Preservation of prior Report/Run/Review identities and all quantitative
  results; only new correction state may be added.
- The smallest reusable Core, CLI, Studio, schema, Agent guidance, or
  documentation repair for each reproduced correction defect.
- A fresh candidate-wheel replay and complete release audit before tagging
  `v0.9.17` when a product change is justified.

### Out of scope

- Recomputing the Path Stress Study, acquiring or comparing providers,
  authenticating Nasdaq/Yahoo/account truth, changing the reported book,
  parameter research, forecasting, Orders, or trading advice.
- Mutating, deleting, withdrawing in place, or silently relabeling any prior
  immutable object.
- A universal editorial workflow, approval roles, signatures, reviewer
  reputation, legal retention system, or OpenAlice version change. OpenAlice
  remains on `0.8.31`.

## Findings and decisions

- 2026-08-01 — Correction is new interpretation over frozen research, not
  mutation of the old truth. A later timestamp alone is insufficient lineage:
  future readers need an executable reason and exact prior identity before
  treating another handoff as current.
- 2026-08-01 — The baseline must remove the unsupported Nasdaq prose rather
  than bind mutable staging after the fact. This fixes the published claim
  while preserving the Review's authority distinction.
- 2026-08-01 — A Review remains independent assessment. It may motivate a
  correction, but the corrected primary-research handoff must not overwrite or
  masquerade as the Review itself.
- 2026-08-01 — The untouched `0.9.16` worker correctly retained the supported
  Path Stress result, removed the unsupported Nasdaq clause, and added exactly
  one ordinary immutable Report. All 233 prior Workspace file hashes and all
  five detached Review file hashes remained unchanged.
- 2026-08-01 — The reproduced defect is not Report authoring. The installed
  product can publish a later Report, and orientation happens to select it by
  timestamp, but correction lineage exists only in Agent-authored prose.
  `report list`, Studio, and Core still present both Reports as equally
  published, with no verified `corrects`, `governingReview`, `current`, or
  `supersededBy` state. Timestamp order is not correction authority.
- 2026-08-01 — The reusable repair must remain append-only. A corrected Report
  will freeze exact prior-Report and governing-Review identity in its own
  immutable package. Currentness will be derived from a verified linear
  correction graph rather than written into or beside the prior Report.
- 2026-08-01 — The admitted contract is deliberately narrow: Project-owned
  Run Reports only, same exact anchor, one current terminal predecessor, one
  exact governing attached/detached Review, and one durable reason. Session
  investigation history is not flattened into this publication path.
- 2026-08-01 — The corrected Report copies the complete verified Review
  package beneath `governing-review/<review-id>/`; the outer Report manifest
  hashes every nested file. Review authority governs editorial lineage but
  never becomes quantitative evidence or promotes observed staging.
- 2026-08-01 — Currentness is derived at load/list time. Core recursively
  verifies the chain, rejects branches and cycles, and exposes current,
  superseded-by, lineage depth, prior Report, governing Review, and reason to
  CLI, Orientation, and Studio. A two-correction unit fixture derives
  `false / false / true` without changing either predecessor.
- 2026-08-01 — A fresh candidate-wheel worker discovered the correction
  contract from installed public help, verified the detached Review, and
  published the corrected handoff on its first attempt. It retained all four
  supported findings, removed the unsupported coverage assertion, and made
  the unbound Nasdaq material an explicit non-authoritative limitation.
