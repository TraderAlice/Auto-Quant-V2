# Causal RL policy state and path-consistent baseline

Status: implemented.

Related: [[docs/design/rl-factor-policy-lab]],
[[docs/design/rl-factor-opportunity-audit]], and
[[docs/design/executed-book-risk-compliance]].

## Problem

At close `t`, portfolio reward is not determined by market features and the
previous action name alone. It also depends on the actual book carried into the
decision:

```text
executed book at t-1
  → drift through return ending at t
  → pretrade book at t
  → distance to each governed sleeve target
  → no-trade / risk repair / cost
  → next-bar reward
```

Targets vary every bar, and a no-trade decision can retain an older book.
Therefore `previous_action=intraday` does not identify current holdings or the
cost of choosing another sleeve. Omitting this state makes the Q environment
non-Markov.

The existing contextual ridge has a separate problem. It learns candidate
rewards from a full candidate-only path, activity rewards from an
activity-only path, and so on. Those paths arrive at the same date with
different books and costs. A dynamic selector comparing those labels is not
comparing actions from one decision state.

## Causal execution state

Every selector receives the existing market state plus:

- drifted pretrade gross, net, cash, maximum weight, and concentration;
- one-way distance from that exact pretrade book to each already-governed
  action target;
- the previous action one-hot.

All values are known at the decision close. They do not include next returns,
realized reward, fold identity, or validation/test labels. The complete scalar
state used by a rollout is retained with that rollout and becomes the source
for rationale reconstruction.

## Path-consistent contextual baseline

The fixed baseline uses deterministic train-only policy improvement:

1. Roll out the neutral `balanced` sleeve on the fold's train dates.
2. At every train decision, evaluate all declared actions for one bar from that
   path's exact pretrade book with the fixed execution/reward primitive.
3. Fit one ridge reward model per action from the shared causal state.
4. Roll out the fitted policy on the same train interval to create its actual
   next behavior path.
5. Repeat for a fixed small number of iterations.
6. Freeze the model before validation and test.

Within each iteration, all action labels at a timestamp share one pretrade
book. Between iterations, the behavior path is regenerated by the newly fitted
policy. Validation and test opportunity evidence never enters training.

This is a strong simple contextual comparator, not a hindsight oracle. It
optimizes one-step governed reward under the state distribution it creates,
does not see future validation/test rows, and does not propagate an ex-post
oracle path.

## Preserved authority

Candidate code still edits only a deterministic row-level encoder. Core owns
actions, reward, execution, state construction, folds, seeds, baseline
training, and acceptance. Historical Runs remain immutable under their
original Judge hash. Neither the Q policy nor the contextual baseline gains
Broker, capital, account, or order authority.

## Bounded fixture result

The controlled six-trial fixture with the causal `volume_regime` candidate
completed in `29.643` seconds. The Q policy reached `32.082895` validation mean
net Sharpe, `66.1111%` one-step local-best hits, `1.4722 / 5` mean selected
rank, and `0.001176` mean one-step regret. It beat the content-locked candidate
factor by `33.868733` Sharpe but still trailed the validation-selected
same-pretrade contextual baseline by `6.032028`.

That result is the intended decision boundary: the richer state repairs a
large representation failure, while the simpler deterministic challenger
still rejects an incremental-RL-value claim.
